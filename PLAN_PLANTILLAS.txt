================================================================================
0. CONTEXTO Y OBJETIVO
================================================================================
Hoy POLIDOC maneja "documentos" (Documento) y "planillas de cambios"
(PlanillaCambios). Se necesita un tercer concepto: PLANTILLAS, entendidas como
documentos EN BLANCO (ej. un DPR vacío con su estructura) que un usuario sube
para que otros lo descarguen, llenen por fuera y luego suban el documento lleno.

Objetivo: que PLANTILLAS, DOCUMENTOS y PLANILLAS DE CAMBIOS convivan y
compartan el mismo flujo de aprobación (misma UX, mismos roles/estados),
reutilizando el modelo Documento para las plantillas.

Relación con lo existente:
  - SGC-FOR-001 = motor de "creación/eliminación" de documentos (Formato).
  - SGC-FOR-005 = motor de "planilla de cambios / modificación" (Formato).
  - La PLANTILLA NO es el Formato FOR-001/005: es un Documento en blanco.

================================================================================
1. CONCEPTOS Y MAPEO
================================================================================
+--------------------------+--------------------------------------+-------------------+
| Concepto (jefa TI)       | Entidad                              | Aprobación hoy     |
+--------------------------+--------------------------------------+-------------------+
| Plantilla (en blanco)    | Documento con es_plantilla=True      | NINGUNA            |
| Documento lleno (crear)  | Documento + SolicitudCambio (FOR-001)| SolicitudAprobacion|
| Planilla de cambios (mod)| PlanillaCambios + SolicitudCambio(FOR005)| AprobacionPlanilla |
+--------------------------+--------------------------------------+-------------------+

Plantilla = Documento en blanco que reutiliza:
  tipo (TipoDocumento), departamento, codigo, clasificación, VersionDocumento,
  vigencia/vencimiento/retención (opcionales) y visibilidad por clasificación.

================================================================================
2. DECISIONES TOMADAS
================================================================================
 D1. Flujo de aprobación: Opción B (conservar modelos; unificar comportamiento).
 D2. Plantilla reutiliza el modelo Documento (no es entidad nueva).
 D3. Discriminador: booleano Documento.es_plantilla.
 D4. Aprobación de creación según rol/jefatura:
       - jefe natural o coordinador CON jefatura delegada vigente (_es_jefe) ->
         pasa directo a estado 'activo' (sin aprobación).
       - trabajador o coordinador SIN jefatura -> 1 paso (jefe del depto).
 D5. Plantilla: 1 paso de aprobación (jefe de departamento). Sin GG.
 D6. Códigos: {DEPTO}-{TIPO}-PLT-{SEC} (o {TIPO}-PLT-{SEC} si sin_prefijo_depto).
     Serie separada de la de documentos.
 D7. Vínculo: Documento.plantilla_origen (FK self) hacia la plantilla usada.
 D8. UI: catálogo /documentos/ pasa a "Plantillas"; sidebar
     "Formularios" -> "Plantillas". Alta reutiliza seleccionar_tipo con
     indicador visual de plantilla.
 D9. FOR existentes (Documento.tipo.key == 'formulario') -> backfill
     es_plantilla=True.
 D10. Modificación de plantilla -> FOR-005 (crear_planilla);
      Eliminación de plantilla -> FOR-001 (eliminar_documento/destruir_documento).
 D11. Vigencia / vencimiento / retención de plantilla: OPCIONALES (como hoy).
 D12. Listado general: NO excluir plantillas; ofrecer listado de todo el modelo
      Documento (documentos + plantillas) con FILTRO es_plantilla.
 D13. plantilla_origen por dos vías:
        - descarga desde el flujo de creación -> autocompletar;
        - subida desde otro lado -> el usuario la selecciona en un desplegable
          (solo plantillas existentes y del mismo tipo).
 D14. TipoDocumento 'formulario' (FOR) se MANTIENE activo.

3. REGLAS DE NEGOCIO
================================================================================
3.1 APROBACIÓN DE CREACIÓN DE PLANTILLA
    Sea `user` el creador y `depto` su departamento:
      if _es_jefe(user):                       # jefe natural o delegado vigente
          documento.estado = 'activo'
          documento.aprobado_por = user
          documento.fecha_aprobacion = now
          (NO se crea SolicitudAprobacionDocumento)
      else:
          crear 1 paso:
            aprobador = depto.jefe  (si no hay -> GG; si no -> None)
            SolicitudAprobacionDocumento(
                documento, accion_solicitud='creacion',
                rol_aprobador='evaluador', es_final=True,
                estado='pendiente' if aprobador else 'esperando',
                solicitante=user, propietario=documento.propietario,
                departamento_origen=depto)
          si aprobador: notificar al jefe.
          si no hay aprobador: avisar_paso_sin_asignar(?, 'evaluación')
            (para plantilla usar el equivalente; ver Fase 2).
    Al aprobar: se REUTILIZA aplicar_cambio (accion='creacion') que ya activa el
    documento, fija vigencia/revisión y sella aprobado_por/fecha_aprobacion.
    autocompletar_respuestas() hace no-op porque la plantilla NO tiene
    SolicitudCambio. => NO se modifica aprobar()/aplicar_cambio().

3.2 CÓDIGOS
    Documento normal  (sin_prefijo_depto=False): {DEPTO}-{TIPO}-{SEC}
    Plantilla         (sin_prefijo_depto=False): {DEPTO}-{TIPO}-PLT-{SEC}
    Documento normal  (sin_prefijo_depto=True) : {TIPO}-{SEC}
    Plantilla         (sin_prefijo_depto=True) : {TIPO}-{PLT}-{SEC}
    La serie se separa filtrando por es_plantilla en generar_codigo_secuencial.
    (Documento.codigo es unique=True -> el segmento PLT evita colisiones.)

3.3 VISIBILIDAD
    Reutilizar permissions.q_documentos_visibles(user) / puede_ver_documento.
    - público: visible para todos.
    - interno: mismo departamento + jefe + propietario.
    - confidencial: jefe del departamento (y grants).
    - restringido: solo admin/propietario/grants.

3.4 MODIFICACIÓN / ELIMINACIÓN
    Reutilizan los flujos existentes sobre Documento:
      - Modificar: crear_planilla (FOR-005).
      - Eliminar: eliminar_documento / destruir_documento (FOR-001).

R: Documento en blanco (no el Formato FOR-001/005); FOR-001=crear/eliminar,
   FOR-005=modificar. Casi todos los documentos usan plantillas como esquema.
P: ¿Cómo se aprueba una plantilla / versiones?
R: Depende del rol del creador (ver D4/D5).
P: ¿Documentos ligados a la plantilla de origen + por TipoDocumento?
R: Sí, y además por TipoDocumento.
P: ¿La plantilla pasa por aprobación / quién sube / modelo / relación tipo /
   versiones?
R: Creación condicional por rol; todos suben; reutilizar Documento; hereda tipo
   y departamento; maneja versiones.
P: ¿Códigos?
R: {DEPTO}-{TIPO}-PLT-{SEC}.
P: ¿Listado general?
R: Listado de todo el modelo Documento (documentos + plantillas) con filtro.
P: ¿plantilla_origen?
R: Dos vías (descarga = autocompleta; subida = el usuario selecciona; la
   plantilla debe existir).

R: Se mantiene activo.
